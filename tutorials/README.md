## Three things this tutorial does that most of the fleet's others do not

**It runs the networks from code it carries, and it converts the checkpoints itself.** No matching framework is installed: `modeling.py` is the upstream matcher and its ALIKED port at the pinned commit, and the two GitHub checkpoint files are plain PyTorch pickles that the notebook audits statically (only the fleet's four allowed globals), unpickles exactly once with the weights-only unpickler, loads strictly and exports as digest-verified safetensors. A runtime that already holds the conversions never opens a pickle.

**Its labels are exact and cost nothing.** Every pair is a photograph and its own warped copy under a known homography, so precision, inlier count and homography accuracy are measured against ground truth rather than an annotator — and the notebook says what that buys and what it does not (no viewpoint change, no occlusion).

**It asks the adaptation a question the frozen matcher actually fails.** ALIKED descriptors and LightGlue's positional encoding are not rotation-invariant; the hard tier rotates up to ±150° and the frozen matcher's precision at 3 px there is 0.500 against 0.999 on the easy tier (build record). The adaptation is selected on validation precision, the held-out cell asserts *not worse* within a rounding margin rather than a gain, and a run that keeps the frozen epoch is a valid outcome the notebook anticipates.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's seven modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative, replace the `resolve_weights_path` checkout-convenience line and remove internal relative package imports), Section 3 carries the snapshot manifest inline (two sources with their conversions) and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, from the immutable release tag `v0.1_arxiv` and the pinned ALIKED commit (never a branch); `verify_snapshot` re-hashes every present entry and asserts the pinned digests and byte counts; `LightGluePipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` audits and converts each source once (static pickle audit, one weights-only unpickle, strict load, safetensors export, digest check), builds the vendored networks from their in-code configuration, loads the safetensors files strictly and picks CUDA when it is visible. No cell outside the carried modules calls `huggingface_hub`, `safetensors`, `urllib`, `torch.optim` or the networks' modules directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 360 research-grade, CC0-licensed iNaturalist photographs (six species, 60 each, one per observer), each pinned in the carried `samples.py` by photo id, byte size and SHA-256 and fetched from `https://inaturalist-open-data.s3.amazonaws.com/photos/<id>/medium.<ext>` (about 39 MB); a cached or fetched file is refused on any mismatch, and every record keeps its observation page and observer login. `build_sample_dataset(seed=SPLIT_SEED)` draws 36 / 8 / 16 photographs per species (216 / 48 / 96) and synthesises one seeded homography pair per photograph (tiers alternating); `check_split_disjoint` asserts no photograph (by decoded-pixel digest of `image0`) is shared. The template adds a second *External access* bullet naming the bucket, the byte count and the CC0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition and pair synthesis) → `validate_dataset` per split + `check_split_disjoint` + `observer_overlap` + refusal probes (validation, with three digests) → `validate_inputs` + `match` with sanity checks + `evaluation_report` on the drawn pair (inference contract) → `evaluate_baselines` + `pipe.evaluate` on the frozen matcher with the per-tier breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `match` + `evaluation_report` on the drawn pair again (inference) → `pipe.save_artifact` → `LightGluePipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** match confidences are thresholded assignment scores, not probabilities of correctness, and the matcher never abstains; precision, inlier count and homography accuracy are computed against exact references (own numpy implementations) and none is a human judgement; no geometric verification and no acceptance threshold ship. The drawn pair re-matched after adaptation carries a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the identity guess, the patch nearest neighbour, the descriptor nearest neighbour and the frozen matcher are scored on the same 96 test pairs as the adapted matcher, on every reading and per tier; every metric is labelled as one seeded split of one sample under synthetic warps with no dispersion estimate, and the notebook says explicitly where the frozen matcher fails (rotation), that the warps exercise no viewpoint change, and that keeping the frozen epoch is a valid outcome.
- **Split integrity (SPL1–SPL8):** the split is seeded and photograph-disjoint; validation (48 pairs) selects the epoch on precision at 3 px and the test split is used for nothing but the final evaluation; observer overlap between splits is printed as an observation, and the notebook states that images from few scenes, sessions or photographers must be split by source.
- **Ceilings (VAL6):** `MIN_SIDE` / `MAX_SIDE` (64 / 1024), `DIVISIBLE_BY` (8), `MAX_IMAGE_SIDE` (4096), the record bounds (4..5,000), the keypoint and match thresholds and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip of photographs is read member by member (no `extractall`) into the runtime, split by image and turned into the same seeded pairs, which flow through the same validation, baselines, fine-tuning, evaluation, export and reload cells. The expected layout and the privacy guidance are stated in the Prerequisites and in Section 4, and the training split's pair table is written to `outputs/lightglue_matching_train.csv`.
- Licence: the matcher weights and the vendored LightGlue code are Apache-2.0 and the ALIKED port and weights BSD-3-Clause, and the notebook, README and card say so; the photographs are CC0 1.0 and are not redistributed — the export records the corpus name, release, bucket, byte count, licence and the tier parameters under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Outputs

The default notebook path writes (under `outputs/`):

- `lightglue_matching_train.csv` — the training split's pair table (id, source, tier, seed, homography, provenance)
- `lightglue_matching_input_manifest.json` — the inference-contract manifest (schema, ceilings, per-image observations, one recorded rejection finding)
- `lightglue_matching_evaluation_report.json` — baselines, frozen and adapted metrics on validation and test, per pair and per tier, the adaptation history
- `lightglue_matching_shapes.json` — the drawn pair's matches before and after adaptation with the reference homography
- `lightglue_matching_adapter/` — `adapter.safetensors` + `manifest.json`
- `lightglue_matching_result.json` — `NOTEBOOK_SOURCE`, model identity, snapshot (with both vendored-code commits), corpus, inference-contract reports, comparison, artifact digest, reload parity, runtime
- `provenance.json`
